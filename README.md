# Automated Classification of Consumer Financial Complaints

Multiclass NLP classification of U.S. consumer financial complaints into ten product
categories, comparing a classical TF-IDF + Logistic Regression pipeline against a
fine-tuned DistilBERT Transformer under identical training and test conditions.

---

## Business problem

Financial institutions receive large volumes of free-text consumer complaints that are
read and routed to the correct department manually. This is slow, costly, and gives no
aggregate visibility when one problem area starts to spike. This project builds a text
classifier that assigns each complaint narrative to its product category automatically,
so complaints can be routed on arrival and emerging issues surface in real time.

---

## Results

Both models were trained on the same 58,036 complaints and scored on the same held-out
test set of 14,509 complaints.

| Metric | TF-IDF + Logistic Regression | DistilBERT |
|---|---|---|
| **Macro F1** (primary) | 0.7973 | **0.8169** |
| Weighted F1 | 0.8158 | **0.8333** |
| Accuracy | 0.8132 | **0.8347** |
| Training time | 7.3 s (CPU) | 18 min 36 s (T4 GPU) |

Macro F1 is the headline metric rather than accuracy, because the classes are imbalanced
(38.2:1 between the largest and smallest) and accuracy would reward a model that simply
favours the majority classes.

**Key finding.** DistilBERT wins by 2.0 points of macro F1, but the gain is not evenly
distributed. It is largest exactly where the classical model is weakest — Debt or credit
management (+0.051), Payday loan (+0.034), Debt collection (+0.027) — and negligible
where distinctive vocabulary already determines the label, such as Student loan (−0.003).
Contextual understanding earns its 153× training cost only in proportion to how much of
the residual error is semantic rather than lexical.

## Pipeline

Run the three notebooks **in order** — each consumes what the previous one produces.

### 1. `data_cleaning.ipynb` — local

Filters the full CFPB Consumer Complaint Database from ~17M rows down to a clean labelled
subset of **407,321 complaints**, using DuckDB to stream from disk. Loading a file this
size into pandas exhausts memory on a normal workstation; DuckDB avoids that entirely.

Three filters are applied: the ten product categories listed below, complaints received
between 2025-01-01 and 2026-08-08, and rows with a non-empty narrative.

**Input:** `complaints.csv` — download from
<https://www.consumerfinance.gov/data-research/consumer-complaints/>
**Output:** `cfpb_filtered.parquet`

Two file-specific settings are required and are documented inside the notebook:
`parallel=false` (DuckDB's parallel CSV reader aborts on this file, because narratives
contain newlines inside quoted fields) and reading `Date received` as VARCHAR so a
malformed date deep in the file becomes a countable NULL rather than a hard cast error.

### 2. `ml_model_lr.ipynb` — local

Balanced sampling (cap of 8,000 per class; the two smallest classes are taken in full),
an 80/20 stratified train/test split, redaction-mask cleaning, TF-IDF vectorisation, and
Logistic Regression with `class_weight='balanced'`.

**Input:** `cfpb_filtered.parquet`
**Outputs:** `train.parquet`, `test.parquet`, `lr_model.joblib`,
`tfidf_vectorizer.joblib`, `confusion_matrix_lr.png`

This notebook writes the shared train/test split. **Both models must be scored on the
same test set** or the comparison in the report is meaningless, which is why the split is
generated once here and reused rather than re-derived in the Colab notebook.

### 3. `dl_model_distilbert.ipynb` — Google Colab, GPU required

Fine-tunes `distilbert-base-uncased` on the same training data, evaluated on the same
test set.

**Before running:** `Runtime → Change runtime type → T4 GPU`. On CPU this takes hours
instead of ~19 minutes. Upload `train.parquet` and `test.parquet` when prompted; the
notebook reads them from `/content/sample_data/`.

**Outputs:** `confusion_matrix_distilbert.png`

## Preprocessing: why the two pipelines differ

The CFPB masks personal data before publication, and these masks are the largest source
of noise in the corpus. The patterns present in the file were identified by inspecting
actual narratives rather than assumed: plain runs (`XXXX`), full date masks
(`XX/XX/XXXX`), scrubber artifacts (`XX/XX/year>`, `XX/XX/scrub>`), partly-real dates
(`XX/XX/2025`), and truncated masks (`XX/XX/`). Masks are stripped *before* lowercasing,
since the `X`s are uppercase.

Beyond mask removal the two pipelines deliberately diverge:

- **TF-IDF pipeline (heavy):** lowercase, strip non-alphabetic characters, remove English
  stopwords. TF-IDF treats every surface form as a separate feature, so this variation
  inflates the vocabulary without adding signal.
- **DistilBERT pipeline (light):** masks removed, nothing else. The Transformer's own
  subword tokenizer handles casing and punctuation, and those carry meaning it uses.
  Applying the TF-IDF cleaning would strip exactly the signal that distinguishes it from
  a bag-of-words model.

## Product categories

Debt collection · Money transfer, virtual currency, or money service · Checking or
savings account · Credit card · Mortgage · Vehicle loan or lease · Student loan · Payday
loan, title loan, personal loan, or advance loan · Prepaid card · Debt or credit
management

The credit-reporting category was excluded: it alone exceeds all others combined and
would have dominated the task.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
jupyter notebook
```

The Colab notebook installs its own dependencies in Step 0 and needs nothing locally.

**Reproducibility:** `RANDOM_STATE = 42` is fixed throughout for sampling, splitting, and
training. Note that each model was trained once — the 2.0-point macro F1 gap is not
accompanied by a confidence interval, and repeated runs across seeds would be needed to
confirm it is stable rather than run-to-run variance.
